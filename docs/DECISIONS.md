# Decisions

"Owner" = stated by the project owner. "Proposed" = suggested during planning; change freely, but note it here.

| # | Decision | By | Notes |
|---|---|---|---|
| D1 | Plugin wraps SubSync's CLI; SubSync is not ported or bundled | Proposed | SubSync is Python plus Whisper and CUDA, about 6 GB |
| D2 | Windows only in v1; worker behind an interface for a later sidecar | Owner | |
| D3 | Hard dependency on File Transformation | Owner | Already installed on the target server |
| D4 | Standalone page served by the plugin; Plugin Pages is the fallback | Proposed | Avoids an extra dependency and GPL-3.0 |
| D5 | One `subsync-cli` process per episode | Proposed | Per-episode result, backup and refresh; costs a model load each time |
| D6 | Only `<video>.en.srt`, `.eng.srt`, `.en.hi.srt` and `.eng.hi.srt` count as English subtitles; one per item, in that order | Owner | HI added 2026-11-11 (D27). Owner keeps naming tidy; other names later |
| D7 | Backup exists only during the sync and is deleted on success | Owner | |
| D8 | One series per request; multiple seasons allowed; UI selection locked to one series | Owner | |
| D9 | Caps 150 per request and 300 queued, configurable | Proposed | |
| D10 | `AllowedUsers` defaults to `AllAuthenticated` (everyone signed in), but non-admins are kept out until SubSync is configured (folder set and `subsync-cli.exe` found) | Owner (2026-11-11) | A fresh install stays admin-only until set up. `GET /Me` returns `reason: not_configured`; the menu entry is hidden for them meanwhile. `AdminOnly` remains a setting |
| D11 | In-memory queue, SQLite state | Proposed | Queue is dropped on restart |
| D12 | Never hash files; fingerprint = path, size, mtime | Proposed | 40,000 episodes |
| D13 | `TidyUpLines` default on (SubSync default) | Proposed | Words are never changed |
| D14 | Stop the queue after 3 consecutive crashes | Proposed | |
| D15 | Progress is episode-level; optional SubSync progress file later | Superseded by D40 | SubSync 1.2.0 had no live progress; 1.3.0's `--progress` lines now drive the running item's share |
| D16 | No Newtonsoft.Json dependency; build File Transformation's `JObject` payload by reflection | Proposed | `RegisterTransformation` takes the server's Newtonsoft `JObject` (File Transformation doesn't bundle Newtonsoft). Shipping our own copy would make the types differ. Take the type from the method's parameter and call `Parse` (M0 S1) |
| D17 | `Microsoft.Data.Sqlite` as a compile-only reference (`ExcludeAssets=runtime`), version not above the server's (12.4 ships 10.0.14) | Proposed | The server already loads it and its native library; a plugin falling back to the default load context gets that copy. Nothing native in our zip. JSONL store stays the fallback behind `StateStore` (M0 S7) |
| D19 | One shared queue, visible to every allowed user; each user cancels only their own items, admins cancel all; inaccessible items are shown without their name | Owner (queue visibility), Proposed (cancel scope, hiding) | A second Start appends to the queue and never starts a second SubSync |
| D20 | Bazarr API key lives in `PluginConfiguration`; the settings page never shows it back (empty field keeps the saved key) and no endpoint of ours returns it | Proposed | Jellyfin 12.4's `PluginsController` is `[Authorize(Policy = Policies.RequiresElevation)]` at class level, so only admins can read plugin configuration. The key goes to Bazarr in the `X-API-KEY` header, never in a URL, so it stays out of logs |
| D21 | Bazarr path mappings are one text setting (`jellyfin => bazarr` per line), not a list type | Proposed | Round-trips through the stock config page and XML config with no custom serializer; bad lines are reported by Test Bazarr and skipped |
| D22 | Settings page has its own scoped design (cards, switches, status pills) instead of stock `emby-*` form controls; icons use the Material Icons font jellyfin-web already ships, by ligature (`<span class="material-icons">save</span>`) | Owner (modern look), Proposed (how) | jellyfin-web 12.4 depends on `material-design-icons-iconfont` 6.7.0 and uses `class="material-icons"` itself, so no CDN or bundled font. Colors mix `currentColor`, so Jellyfin's light themes stay readable. `WebTests` checks that every setting has a field and that the page loads nothing external |
| D23 | Startup recovery reads a backup journal (`in_flight` table, written before each `.bak` is created) instead of scanning for `.bak` files | Proposed | A scan would walk the whole 40,000-episode library (rule 6). No journal, no backup, no run. An existing `.bak` is never overwritten |
| D24 | When the queue stops itself (exit 7, 3 crashes), remaining queued items are cancelled with the reason, not paused | Proposed | Simple to reason about; users press Start again, and synced episodes are skipped anyway. `stopReason` stays visible until the next Start |
| D25 | Finished queue items stay listed until their owner clears them or for 24 hours; an episode is never queued twice | Superseded in part by D44 (one minute, plus the failed-syncs log); "never queued twice" stands | Lets everyone see recent results after the queue goes idle |
| D29 | Every SubSync run is put in a kill-on-close Windows Job Object, and its pid is recorded so startup kills a leftover run before recovery | Proposed (from a live finding) | Killing Jellyfin left `subsync-cli.exe` and its `python.exe` children running. An orphan finishing after startup recovery would overwrite the restored subtitle with its backup already deleted. Plain P/Invoke to kernel32, no new dependency |
| D18 | License: GPL-3.0 | Owner (2026-11-11: "whatever is convenient for a free to use open source plugin on GitHub") | `LICENSE` in the repo root. Matches Jellyfin's official plugin template and most Jellyfin plugins; the plugin compiles against GPL server packages |
| D26 | Movies are supported, per `MOVIES-PLAN.md` | Owner (2026-11-11) | Built 2026-11-11 with the plan's proposed rules: no mixing movies and episodes in one request (`mixed_selection`), no series lock for movies. Owner confirmed both rules on 2026-11-11 |
| D27 | Hearing-impaired sidecars (`.en.hi.srt`, `.eng.hi.srt`) are processed | Owner (2026-11-11) | Lower priority than plain English when several exist. SubSync 1.3.0 and later: every run passes `--output <subtitle> --overwrite`, so the `.hi` file is re-timed in place like any other name, and a plain `.en.srt` next to it is never touched or a reason to refuse (2026-11-12). SubSync 1.2.0 (or an unreadable version) rejects `--suffix en.hi` ("invalid choice", exit 6, S5), so there the worker still runs with the plain tag, moves the result over the `.hi` file, refuses when a plain `.en.srt` already exists, and removes a stray result on failure |
| D28 | Bazarr: everyone who may use Subtitle Fixer can search and download, but Find subtitles appears only on episodes and movies with no English sidecar; everywhere else the page only re-times | Owner (2026-11-11) | No separate Bazarr permission. The server rejects Bazarr calls for items that already have a sidecar (`409 has_subtitle`) |
| D30 | Bazarr manual search gets a 90 s timeout; other Bazarr calls keep 30 s | Proposed | Search asks every enabled provider in turn: 4.9 to 5.6 s for three providers on the test Bazarr 1.6.2, and accounts like opensubtitles can be much slower. The page shows a spinner meanwhile |
| D31 | Find subtitles shows only English, non-forced results, and is refused where the item has no English audio | Proposed | Bazarr saves forced subtitles as `.en.forced.srt`, which the fixer never re-times (D6), and an English subtitle can't be re-timed to non-English audio. The dialog counts the hidden results |
| D32 | The Find subtitles dialog shows every allowed user the Resource line: the video path as Bazarr reports it, which is a server file path | Owner (2026-11-11: keep the full path) | BAZARR-PLAN.md asks for it so users can see the match is right. Only users who can already access the item in Jellyfin see it, and Jellyfin itself gives them the path: in v12.4, `Emby.Server.Implementations/Dto/DtoService.cs` (line 1244) sets `dto.Path` whenever `ItemFields.Path` is requested, with no admin check in that file (from source), and PlaybackInfo returned `MediaSources[].Path` to a user with access on Testflix (live, main track). Showing non-admins only the file name was considered and declined |
| D33 | Bazarr download: back up every subtitle next to the video in memory (not a file), wait up to 2 minutes for a valid accepted sidecar, restore anything Bazarr changed, then clear the `done` record and queue one `source:bazarr` job; SubSync must be configured and the queue must have room before anything is downloaded | Proposed | Bazarr 1.6.2 downloads in a background job and never reports the result to the API (BAZARR-API.md), so the file appearing is the only signal. An in-memory copy can't collide with JobRunner's `.bak` or be left behind by a crash; it's normally empty anyway, because D28 refuses items that have a subtitle. `original_format=False` keeps the result `.srt`. Checking capacity first avoids a downloaded subtitle nobody re-times. Once Bazarr accepts, the wait ignores the browser's cancellation, so closing the dialog doesn't undo a download that is about to land. If Bazarr's job finishes only after the 2-minute wait, its subtitle stays on disk unqueued: nothing is lost, and selecting the item re-times it |
| D34 | The SubSync time limit per item is the larger of `EpisodeTimeoutMinutes` (now labelled "Minimum time limit") and twice the video's runtime plus 10 minutes; the setting alone applies when Jellyfin has no runtime | Owner asked (2026-11-11), Proposed (formula) | Live: a 112-minute movie on CPU needs about 33 minutes, so the fixed 30 would stop it. Detecting CPU mode is unreliable, because `check` doesn't say and a GPU can silently fall back. 2x covers the slowest CPUs in the README table (about 1.5x real time). The limit only guards against a hung run, so erring long costs nothing on healthy runs |
| D35 | Subtitle Fixer opens as a pop-up over Jellyfin (the page in a same-origin iframe, `?embedded=1`) instead of replacing Jellyfin | Owner asked (2026-11-11) | Jellyfin stays where the user was. Ctrl, Shift or middle click still opens the full page, and `/SubtitleFixer/Page` still works on its own. Verified on Testflix 12.4: Jellyfin sends no header that blocks framing its own pages |
| D36 | The settings page is listed in the dashboard sidebar (`EnableInMainMenu`, icon `subtitles`) | Owner asked (2026-11-11) | One click instead of Plugins → Subtitle Fixer → Settings. jellyfin-web 12.4 lists these pages in its plugin section, next to other plugins such as KefinTweaks. Verified on Testflix |
| D37 | The page is marked `translate="no"` | Owner asked (2026-11-11) | Chrome kept offering to translate it, because the Jellyfin UI language differs from the page's. The page is English-only and short |
| D38 | GPU or CPU on the settings page comes from the last sync, kept in memory | Proposed | `check` never says (S5). SubSync 1.3.0 and later: the `device` progress event, taken as it arrives (it comes again if a GPU problem switches to the CPU, and the latest wins), then the report's `speech_recognition` once the run ends. Fallback for 1.2.0: the "Speech recognition:" line, the last one in the output (SubSync prints it again after a switch; the first one used to win). A cached run that listened to nothing keeps the previous answer. Until the first sync after a restart, the page says it will show after the first sync |
| D39 | Releases are made by `build\release.ps1` on the owner's PC with `gh`, not by GitHub Actions; the repository URL is `releases/latest/download/manifest.json`, a manifest attached to each release that carries every version | Proposed | The owner wants everything sent in under their own name; a workflow would tag and release as github-actions. A manifest attached to the release needs no commit to `main` per release. Jellyfin 12.4 fetches the manifest and the zip with its default `HttpClient` (`SocketsHttpHandler`, which follows GitHub's redirects) and checks the zip's MD5 against `checksum` (`InstallationManager.cs`). CI (`build.yml`) still builds and tests every push. Tested on Testflix with a local repository |
| D40 | The running item's progress: SubSync's live stage ("Reading audio…", "Listening…", "Matching lines…") plus a share of the bar. With SubSync 1.3.0 `--progress`, during listening the share is listening's expected slice of the run filled by SubSync's own `percent` (the server sends it as `percent`); otherwise, and for 1.2.0, it is elapsed time over an expected time. The bar holds below 95% until the item ends and never moves backwards. The expected time is start-up plus the video's length times a speed ratio learned from finished runs on this server (before the first: 0.04 if the last run said GPU, else 0.33, plus 15 s start-up). From 1.3.0 runs it learns start-up as the process's wall time minus `read_audio + listen + match` (`model_load_seconds` when the wall time is missing), reading and listening per second of video, and matching seconds. Runs whose transcript came from SubSync's cache teach nothing: 1.3.0 says so (`timings.from_cache`, or a run that never reached reading audio or listening), and without timings a run under 1% of the video's length or under 10 s is taken as cached | Owner reported (2026-11-11: "the progress bar was just stuck on 0%"); 1.3.0 use and the cached-run fix 2026-11-12 (owner approved the start-up formula and the 1% / 10 s rule) | SubSync 1.2.0 prints no percentage, and the bar only counted finished items, so one item showed 0% for its whole run. A cached run (a Retry from the failed-syncs log, or a re-sync after a no-match) takes a few seconds and dragged the learned ratio far too low. Start-up from wall time rather than `model_load_seconds`: 1.3.0 reads the audio while the model loads, so adding both would count that overlap twice, and `model_load_seconds` leaves out the self-check and Python start. 1% rather than 2%: a fast GPU can finish a 45-minute episode near 2% of its length, and a cached run is a few seconds, far below 1% (27 s). Everything lives in memory and resets on restart; a wrong guess only moves the bar, never the time limit (D34). With piped output SubSync 1.2.0 writes the stage lines only to its `logs\cli.log`, not to stdout (verified 2026-11-12), so for 1.2.0 the worker follows that file during a run (`LogTail`); only one SubSync runs at a time, so its new lines are ours. With 1.3.0 the `PROGRESS` lines on stdout replace it |
| D41 | The settings page draws its icons as inline SVG (Material Icons paths as bundled in jellyfin-web 12.4), not with the icon font | Owner reported (2026-11-11: the button read "_OUTLINE Test SubSync" on the main server) | A theme or another plugin on the main server swapped the icon font for one without the `play_circle_outline` ligature. Inline SVG doesn't depend on whatever font is loaded |
| D42 | When Test Bazarr fails (an HTTP error, or an answer that isn't Bazarr's API), the message names the exact URL tried, and the plugin reads Bazarr's own page at the typed address and at the server root to suggest the right address | Owner reported (2026-11-11: "Bazarr answered HTTP 404 even though the address is correct") | Bazarr's page embeds its URL Base (`window.Bazarr = … "baseUrl": "/bazarr"`), and with a URL Base set, Bazarr 1.6.2 redirects every other path to that page (verified on the test Bazarr). A page path pasted from the browser gets Bazarr's page back, not JSON. A 404 usually means another service or a proxy at that address. The page also carries Bazarr's API key, so it is never logged or returned |
| D43 | Admins choose which TV and movie libraries Subtitle Fixer offers (`AllowedLibraryIds`; empty = every library, including ones added later). It applies to everyone, administrators too, on top of each user's own Jellyfin library access. `LibraryScopeFacade` wraps the Jellyfin facade and every service reads the library through it, so browsing, search, selection, the runner and Bazarr all treat an item elsewhere as not found. An item counts as in a library by its breadcrumb's library (the series' or movie's collection folder); an item whose library can't be found is out of scope when libraries are chosen, and a setting whose ids are all unreadable allows nothing | Owner requested (2026-11-12) | One check point instead of one per endpoint, so a new endpoint can't forget it. Applying it to admins keeps "what the plugin works on" one rule; an admin who wants a library adds it in the settings. Search with libraries chosen runs one recursive `folder.GetItems` per allowed library (the same call that already pages a library's series) and merges the pages, instead of guessing how `AncestorIds`/`TopParentIds` treat a collection folder on 12.4 (live check in `M0-LIVE-CHECKS.md`). The settings page lists libraries from `GET /Admin/Libraries`, which reads the unwrapped facade with the admin's own access; ids of chosen libraries the admin can't see are kept on save |
| D44 | Finished queue items leave the queue list one minute after they end (was 24 hours). Failed and check outcomes are written, when they end, to a failed-syncs log in `state.db` (`failed_syncs`, newest 500), which the page shows as a "Failed syncs" panel with Retry; admins see and can clear every entry, other users see only their own | Owner requested (2026-11-12) | The list grew with every run and buried the current one. Writing the log at completion (not at expiry) means a restart or a missed poll can't lose an entry. Check outcomes are logged too: they also need a person to look, and would otherwise vanish after a minute. The stop reason is kept after its items expire, until the next Start, so a stopped queue still says why |

## Deferred
Embedded subtitle extraction, other languages, movies, other names and formats (`.ass`, `.vtt`), Linux sidecar, parallel jobs.
